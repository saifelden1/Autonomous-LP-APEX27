# AI Pair-Programming Charter for APEX Recruits

Welcome to **APEX Autonomous Systems** (Formula Student AI & ERC 27). In our team, AI is not a shortcut to skip learning; it is your 24/7 senior robotics pair-programmer. 

If you copy-paste AI code without understanding it, you will fail the onboarding review and freeze during competition trackside debugging. Follow this charter strictly.

---

## 1. The Three Mandatory AI Rules

### Rule 1: The "Explain-Before-Run" Protocol
Before pasting or running any block of code generated by an AI assistant:
* Ask the AI:
  > *"Explain line-by-line what this node does. What is the execution flow, which callbacks run concurrently, and what ROS 2 executor model is being used?"*
* You must be able to explain every single line in your pull request defense.

### Rule 2: The "Failure-First" Backtrace Protocol
When terminal commands error out or nodes crash:
* **DO NOT** ask: *"It didn't work, fix it."*
* **DO**: Feed the full terminal backtrace and ask:
  > *"Analyze this backtrace. Did this crash due to an unspun node, a QoS reliability/durability mismatch, an unhandled exception in a timer callback, or a missing transform in TF2?"*

### Rule 3: Specification-Driven Prompting
Never ask an AI to design an autonomous module from a vague prompt. Provide an explicit architecture specification:
1. **Node Name**: (e.g., `telemetry_watchdog_node`)
2. **Subscriptions**: Topic names, types (`sensor_msgs/msg/LaserScan`), and QoS profiles (`SensorDataQoS`).
3. **Publications**: Topic names, types (`geometry_msgs/msg/Twist`).
4. **Services / Actions**: Request/response contracts.
5. **Parameters**: Names, types, default values.
6. **Expected Fail-Safe Behavior**: What happens when sensor feeds disconnect.

## 2. Five Common AI Traps in ROS 2 (Watch Out!)

| Trap | Why AI Makes It | How to Catch It |
| :--- | :--- | :--- |
| **ROS 1 vs ROS 2 Confusion** | AI mixes `rospy` or `catkin_make` with `rclpy` and `colcon`. | Always ensure imports use `rclpy` and builds use `colcon build --symlink-install`. |
| **Blocking Sleep Inside Callbacks** | AI often suggests `time.sleep()` inside callbacks, freezing the single-threaded executor. | Replace with ROS 2 timers (`create_timer`) or multi-threaded executors. |
| **QoS Mismatch Silence** | Publisher uses `Reliable`, Subscriber uses `BestEffort`. Node runs without error, but no messages arrive. | Verify matching QoS profiles using `ros2 topic info --verbose <topic>`. |
| **Inverted TF Frames** | AI swaps parent and child frames (e.g., publishing `base_link ➔ odom` instead of `odom ➔ base_link`). | Check coordinate convention against ROS REP-105 standard. |
| **Missing Package Dependencies** | AI generates Python imports but forgets to add `<exec_depend>` to `package.xml` or entry points in `setup.py`. | Colcon will build successfully, but `ros2 run` will throw `No module found`. |

## 3. Recommended Prompt Templates

### Template A: Architecture & Boilerplate Generation
```text
I am developing a ROS 2 Humble node in Python for the APEX team.
Node Name: <name>
Subscriptions:
  - Topic: <topic_name>, Type: <msg_type>, QoS: <profile>
Publications:
  - Topic: <topic_name>, Type: <msg_type>
Parameters:
  - <param_name> (type, default)
Behavior:
  - <Brief description of logic>
Please generate only the node class following PEP-8 and ROS 2 standard lifecycle best practices. Include descriptive comments on executor handling.
```

### Template B: Error & Bug Diagnosis
```text
My ROS 2 node crashed with the following error output:
<PASTE TERMINAL LOG HERE>

Code context:
<PASTE RELEVANT FUNCTION HERE>

Explain:
1. What was the exact root cause?
2. What ROS 2 concept was violated?
3. How do I fix it surgically without altering unrelated logic?
```
